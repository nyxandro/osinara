# gws - Shared Reference

## Osinara Execution Boundary

Never invoke `gws` through `bash`, a script, a subprocess, or an absolute binary
path. Native Bash intentionally has neither the Google profile nor the `gws`
binary. Every command shown in these skills is command documentation only.

Execute it with `execute_google_workspace` and an exact argument array that omits
the leading `gws`. Preserve each argument as a separate array element; do not add
shell quoting, pipes, redirects, substitutions, or command chaining. For example:

```json
{"argv":["calendar","events","list","--params","{\"calendarId\":\"primary\"}"]}
```

The boundary classifies the reviewed command path as read or mutation. Every
mutation is paused for human approval and displays the complete argv, including all
recipients, IDs, bodies, ranges, and other material parameters. Never use
`ask_question` as a substitute for this approval.

## Osinara Runtime Authentication

Osinara selects exactly one Google credential profile inside the typed execution
boundary. In a private chat, this is the current
user's personal profile. In a registered family group, this is the separate
shared family profile. Do not infer, switch, print, copy, export, or inspect
credential files.

Credential files are not available to the model or native Bash. Never attempt to
locate, inspect, print, copy, export, or infer them.

Do not run authentication commands from the agent session:

```bash
gws auth login
gws auth logout
gws auth export
```

If `gws` reports missing credentials, call `manage_google_workspace_connection`
with `action: "status"` first. If the profile is disconnected, call it with
`action: "connect"` and give the user the protected OAuth link. Disconnect only
after an explicit user request. In family scope, only the owner may connect,
replace, or disconnect the shared profile.

## Route-Specific Output Flags

The Osinara allowlist is authoritative. A flag is usable only when the loaded
service/helper skill lists it for that exact route. Do not assume a CLI-global
flag is accepted by every helper.

| Flag | Description |
|------|-------------|
| `--format <FORMAT>` | Output format: `json` (default), `table`, `yaml`, `csv` |
| `--dry-run` | Validate locally only on routes whose skill explicitly lists it |
| `--sanitize <TEMPLATE>` | Unavailable unless the exact route skill and allowlist list it |

## CLI Syntax

```bash
gws <service> <resource> [sub-resource] <method> [flags]
```

### Method Flags

| Flag | Description |
|------|-------------|
| `--params '{"key": "val"}'` | URL/query parameters |
| `--json '{"key": "val"}'` | Request body |
| `-o, --output <PATH>` | Not available through `execute_google_workspace` |
| `--upload <PATH>` | Not available through `execute_google_workspace` |
| `--page-all` | Auto-paginate (NDJSON output) |
| `--page-limit <N>` | Max pages when using --page-all (default: 10) |
| `--page-delay <MS>` | Delay between pages in ms (default: 100) |

## Security Rules

- **Never** output secrets (API keys, tokens) directly
- Every allowlisted mutation uses the boundary's mandatory human approval; service
  notes may explain impact but never weaken or replace that approval
- Use `--dry-run` only when the exact route skill lists it
- Do not pass `--sanitize` unless the exact route skill lists it
- Use only the automatic human approval generated by `execute_google_workspace` for
  mutations; one approval applies to exactly one complete argv and one execution
- Do not automatically retry failed `gws` mutations; inspect the error and
  current state first so a retry cannot duplicate a side effect

## Argument Array Tips

- Sheet ranges like `Sheet1!A1` and JSON are plain array values. Never wrap them
  in shell quotes; quoting characters would become part of the Google argument.
- JSON supplied to `--params` and `--json` is one plain string array element.
- Pipes and output redirection are not argv.
- Do not pass `--upload`, `--output`, `--output-dir`, `--attach`, `-a`, or `-o`.
  File-consuming arguments remain disabled until Osinara can stage regular files outside the
  credential-bearing container; use non-file API fields or another application tool instead.
