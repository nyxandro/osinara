# Проверка памяти и подготовленные улучшения

## Решение

Краткие и полные версии фактов не вводим. Проверка production выполнена через SSH
только read-only запросами. Время снимка базы: 6 сентября 2026, около 20:30 UTC.
Данные относятся к production v0.21.4, до применения новых правил отбора.

| Выборка | Количество | Среднее, символов | Медиана | 95-й процентиль | Максимум |
| --- | ---: | ---: | ---: | ---: | ---: |
| Активная память | 865 | 265 | 195 | 495 | 3878 |
| С установленным источником | 796 | 209 | 193 | 415 | 817 |

За последние семь дней создано 512 активных записей, самая длинная содержит 563 символа.
22 записи длиннее 1000 символов относятся к `legacy_unresolved`. Из 15 записей длиннее
1500 символов 13 являются старыми новостными дайджестами. Размеры измерены SQL
`char_length(content)`, без служебных полей, это не токены.

Сохранения уже содержат рабочий опыт, планы поездок, рекомендации сервисов и ссылки.
В исследованных примерах сообщения размером 1622-3335 символов становились записями
размером 243-483 символа. Это примеры сокращения, а не оценка полноты и точности всей памяти.

## Остановка групповой проверки

Группа: `Остриков пилит агентов`.

- Пакет: `dd0a3b2d-5c8d-45a0-941b-5ef59b4d4017`.
- Лейн: `ccdffe91-708e-4480-a77a-d1ba3aae0e4d`.
- Предшественник: `18113`, единственный источник: `18114`.
- Статус: `ambiguous`, код `AGENT_MEMORY_REVIEW_INTERACTIVE_START_AMBIGUOUS`.
- Отсутствуют `eve_session_id`, `eve_turn_id`, связанный набор источников хода и evidence
  сохранённых фактов по исходному сообщению.
- Исходная canonical-сессия закрыта 5 сентября; её менять или переоткрывать не требуется.
- За пакетом есть уже завершённые пакеты до `18126`, их повторять нельзя.
- После остановившегося курсора было 1064 человеческих сообщения. Это не число гарантированно
  пропущенных сообщений: несколько последующих пакетов уже успели завершиться.
- Первоначальное предупреждение владельцу было доставлено, но восстановления старого состояния
  после изменения runtime не произошло.

Подготовлен узкий переход только для этого класса старых состояний. При полном сохранённом
наборе источников и доказанном отсутствии обработки пакет один раз возвращается в штатную
фоновую очередь с тем же ID, диапазоном и связями. Источники не дополняются уже проверенными
сообщениями. Миграция 089 разрешает короткий фоновый пакет только для такого аудированного
восстановления; обычные фоновые пакеты по-прежнему содержат 50 сообщений.

Любая привязка к Eve, исходный набор хода, evidence, повреждение ссылок на сообщения,
незакрытая исходная сессия или уже использованная попытка исключают автоматическое восстановление.
Проверка идёт под блокировками PostgreSQL. Уже завершённые наследники остаются неизменными;
курсор проходит через них только после успешной обработки восстановленного пакета.

## Диагностика

- `AGENT_MEMORY_REVIEW_LANE_METRICS`: курсор, состояние первого пакета, число сообщений
  после курсора и дата самого старого. Счётчик включает сообщения текущих выполняемых пакетов.
- `AGENT_MEMORY_REVIEW_LANE_BLOCKED`: терминальный пакет блокирует продолжение.
  Отсутствующее предупреждение добавляется через существующий outbox; одна запись на пакет
  и поколение восстановления, без автоматического повтора неоднозначной Telegram-доставки.
- `AGENT_MEMORY_RETRIEVAL_METRICS`: размер и refs автоматической подборки, профилей и нитей.
- `AGENT_MEMORY_SEARCH_METRICS`: отдельные вызовы поиска с session/turn/call ID, размером,
  refs и результатом. Текст вопроса и содержимое памяти в лог не попадают.

Новые runtime-счётчики символов используют JS UTF-16 units, как существующие метрики
вызова модели. Их нельзя выдавать за точное число токенов. Ошибка чтения оставляет объём
неизвестным (`null`), а не подтверждённым нулём.

## Старые записи

Старую память не меняли. Рекомендации для отдельного согласования:

| Категория | Предлагаемое действие | Условие |
| --- | --- | --- |
| Старые новостные дайджесты | Рассмотреть архивирование вне активных фактов | Только после решения владельца; новости не перепроверены |
| Старые правила оформления | Сопоставить с текущими настройками общения | Не переносить автоматически между чатами и не активировать как инструкции |
| Обзор книги и содержательные справки | Оставить до проверки полезности и источника | Большой размер сам по себе не основание для удаления |
| Остальные `legacy_unresolved` | Проверять выборочно при использовании | Метка старого происхождения не доказывает ошибочность |

## Проверка после будущей выкладки

На этапе подготовки пользователь разрешил только код и проверки, без изменения production.
После завершения проверки отдельно согласован общий выпуск v0.21.5 через штатный CI/CD.
Фактическое восстановление production проверяется после owner-подтверждения установки;
приведённые ниже действия не являются утверждением, что оно уже состоялось.

После отдельного разрешения использовать только canonical CI/CD и штатный deployment controller:

1. Проверить свежий снимок пакета, наличие исходного сообщения и неизменность evidence.
2. Выпустить проверенный код с миграцией 089 и новыми инструкциями.
3. Убедиться, что минутный диспетчер восстановил пакет один раз, сохранил audit и обработал
   именно его источник; уже завершённые пакеты не получили новых ходов.
4. Проверить продвижение курсора через `18126` и последующую обработку накопленного хвоста.
   Не форсировать повтор неясного model call и не перематывать курсор прямым SQL.
5. На небольшом согласованном наборе реальных обращений проверить путь от сообщения до ответа:
   обычный опыт работы; предварительный план; полезная ссылка с пояснением;
   вопрос "дай ту ссылку" с достаточным контекстом; болтовня без факта.
6. Для пропуска различать: источник ещё не проверен, факт не сохранён, поиск не нашёл,
   найденный факт не использован. Проверять автора, время и сохранность точного URL.

Рост частоты запоминания и качество ответа в живом чате до этой проверки не подтверждены.

## Отдельное замечание ревью

Обнаружена прежняя несогласованность, не изменённая в этой задаче: фоновая очередь отбирает
`user` и `telegram_bot`, но `memoryTurnSourceRepository.bindReview` принимает только `user`.
Пакет со сторонним ботом может не пройти привязку источников. Для найденного старого
пакета это не причина сбоя: его единственный источник человеческий. Обработку сообщений
ботов следует исправлять отдельно с проверкой соответствующего контракта.

Дополнение после отдельного согласования: подготовлена правка общего пути `user`/`telegram_bot`,
включая observer на пятидесятом сообщении, привязку и чтение источника, а также реальный тип
отправителя в JSON фоновой проверки. Проверки проходят до настоящего `remember`, записи evidence
с исходным автором и завершения очереди, а не только до старта хода. Для пакета
`a96eb59c-49e4-4dd6-9318-54b50d06548a` (18330-18379) владелец затем разрешил потерю
несохранённых фактов и отказался от восстановления. Отдельная миграция и её тесты удалены.
При будущей выкладке исправления этот пакет нужно разово пропустить существующим механизмом
завершения пакетов, после повторной проверки его состояния и завершения исходного хода.
Ожидающие следующие пакеты не удалять и не перескакивать через них. Удаление миграции само
по себе не освобождает очередь. Пропуск на production на этом этапе не выполнялся.

## Выполненные проверки

- Чистая установка зависимостей при сборке штатного Docker test image, включая локальный патч Eve.
- Миграции и typecheck внутри тестового контейнера.
- Полный Docker-прогон: 2360 тестов прошли, 3 отдельные opt-in проверки качества поиска
  и восстановления внешней модели пропущены штатной конфигурацией.
- `npm run build` прошёл локально и в Docker; свежий discovery содержит единственный
  application resolver `tools/capabilities.ts`, без ошибок и предупреждений.
- 15 тестов нового восстановления включают безопасность источников, завершённых наследников,
  единственность аренды, запрет обычного короткого background-пакета и детерминированную
  проверку совместимости блокировок при добавлении предупреждения.
- Финальная проверка выпуска дополнительно воспроизвела ожидание двух лейнов в разном порядке.
  Восстановление перенесено после общего упорядоченного захвата лейнов; создание предупреждения
  не ждёт пакет, занятый обработчиком завершения. Оба сценария защищены отдельными тестами.
- Независимое ревью: найденная взаимная блокировка воспроизведена тестом и исправлена;
  повторная проверка новых замечаний не выявила.
- Тестовый PostgreSQL и временная Compose-сеть удалены после прогона.
