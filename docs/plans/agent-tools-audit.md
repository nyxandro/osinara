Сделанное по нему (v0.43.0 и коммиты 22.10) убрано, история — в git. Здесь только то, что осталось.

## 1. Ошибка проверки полей — в общий формат

**Что происходит.** Если модель передала поле не того вида, AI SDK отклоняет вызов до выполнения, и модель
получает сырой текст вида `AI_InvalidToolInputError … Type validation failed …` вместо общего формата с `code`,
`correction` и `retryable`. Такой вызов попадает в журнал с пустым `input` и не виден в метрике
`AGENT_TOOL_CALL_METRICS`: ядро берёт готовый результат AI SDK как есть (`synthesizedOutputs` в
`agent/runtime/turn/step-calls.ts`). С 04.10 — 10 случаев, модель каждый раз исправлялась на следующем шаге.

**Чем мешает.** Лишний шаг модели на каждую ошибку; отказы не видны в метриках; из-за этого схемы держат
ослабленными — `kind` и `sensitivity` в `manage_memory` (`agent/lib/tools/manage_memory.ts`), `scope` в
`manage_reminder` (`agent/lib/tools/manage_reminder.ts`) — свободные строки, допустимые значения модель узнаёт
только из ошибки.

**Что сделать.** Отказ проверки полей превращать в `AGENT_TOOL_INPUT_INVALID` с полями `field` и `correction`;
писать его в метрику; в журнал сохранять фактически переданные поля. После этого сделать перечисленные поля
строгими (`enum`), чтобы модель видела допустимые значения заранее.

**Готово, когда** тест ядра показывает: вызов с неверным полем даёт модели общий формат ошибки, строку метрики
и запись журнала с переданными полями; три поля выше — `enum`.

## 2. `web_fetch` дочитывает длинную страницу

**Что происходит.** Страница отдаётся модели до 50 КБ и 2 000 строк, дальше обрезается
(`agent/lib/tool-policy/controlled-web-fetch.ts`); параметра «продолжить с места» нет. По журналу на 21.10
обрезано 4 страницы из 28 — ответ по длинной статье или документации строится по её началу.

**Что сделать.** Параметр смещения в схеме и в ответе — где кончилась отданная порция и есть ли продолжение.

**Готово, когда** тест показывает: вторая порция начинается ровно там, где кончилась первая, и в ответе видно,
есть ли третья.

## 3. `search_memories` отвечает в одной форме

**Что происходит.** Обычно ответ — массив записей, а когда смысловая ветка недоступна — объект с
`incompleteSelection`, и описанию инструмента приходится объяснять обе формы
(`agent/lib/tools/search_memories.ts`). Поле `query` обязательно даже при поиске за период, где слова запроса в
отборе не участвуют, — модели приходится придумывать значение.

**Что сделать.** Всегда возвращать объект `{items, incompleteSelection}`; `query` сделать необязательным, когда
заданы `from` и `to`, и требовать хотя бы одно из двух.

**Готово, когда** тесты контракта покрывают обе ветки ответа одной формой и поиск за период без `query`.

## 4. `list_group_history` возвращает применённые фильтры

**Что происходит.** Описания `list_group_history` и `read_scheduled_group_history` запрещают параллельные вызовы:
в ответе не видно, к какому фильтру он относится. Поиск по длинной истории группы идёт шаг за шагом.

**Что сделать.** Возвращать в ответе применённые фильтры (и курсор для снимка истории); после этого убрать
запрет из описаний.

**Готово, когда** тест показывает фильтры в ответе, а описания не запрещают параллельные вызовы.

## 5. Предел для `context` у `grep`

**Что происходит.** Число строк контекста ограничено только снизу (`GREP_INPUT_SCHEMA` в
`agent/runtime/tools/grep.ts`). Вывод всё равно режется до 50 КБ, так что вреда нет, но модели не видно
разумной границы.

**Что сделать.** Верхний предел в схеме.

**Готово, когда** схема отклоняет значение выше предела.

## Решение владельца: подгрузка редких инструментов по требованию

Отложено владельцем 15.10.2026 по замеру на `qwen3.8-27b`: описания инструментов — 17 тыс. токенов из 37,6 тыс.
свежего запроса личного чата; выбор инструмента на 26 просьбах × 3 — 77 из 78 верно при 43 инструментах; смена
набора инструментов сбрасывает кэш провайдера (первый ответ в длинном чате ~48 с вместо ~2 с).

- Даёт: короче запрос, меньше риск ошибки выбора, когда инструментов станет больше.
- Стоит: изменение в ядре; сброс кэша в ходе, где инструменты подгрузятся.
- Закрепляет: двухуровневый набор инструментов, который придётся поддерживать.

Рекомендация: не возвращаться без нового повода — инструментов в личном чате больше 50 или ошибки выбора в
длинных чатах.
