# v0.82.2 — обновление пережидает короткий сбой GitHub и не пишет «не удалось» после успеха

Две правки выкатки (PR #582) по решению владельца 25.11.2026 — после того как выкатку v0.82.0 сорвал сбой GitHub.
Для пользователей бота ничего не меняется.

Миграций нет, переиндексация памяти не нужна, ручных шагов до и после кнопки нет. Это вторая выкатка после
ускорения (#577): копия папок песочниц впервые переносит только изменения, а образы — только изменившиеся слои.

## Что изменилось для владельца

- **Короткий сбой GitHub больше не срывает обновление.** 25.11 в 02:40 UTC GitHub около четырёх минут отвечал
  ошибкой 504 на запрос описания релиза, и выкатка v0.82.0 отказала на первом шаге; ту же версию повторно не
  предлагают, пришлось выпускать v0.82.1. Теперь сервер повторяет такой запрос каждые 30 секунд, до 5 минут, и
  только при временных ошибках — таймаут или ответы 408, 429, 500, 502, 503, 504. Окончательный отказ (например,
  «не найдено») по-прежнему останавливает выкатку сразу. Все эти запросы только читают.
- **После «успешно установлено» не придёт «не удалось».** Когда обновление уже записано как успешное и вы
  получили сообщение об этом, сбой последующей уборки — удаления старых образов, старых версий скрипта выкатки
  или списанных копий — больше не присылает «Не удалось однозначно завершить обновление». Он только пишется в
  журнал, а уборку повторит следующая выкатка.

## Наблюдение

- В журнале выкатки (`journalctl -u osinara-deploy.service`) каждый повтор запроса к GitHub — строка
  `Warning: Problem : HTTP error. Will retry in 30 seconds. N retries left.`
- `DEPLOY_POST_SUCCESS_STEP_FAILED` — после успешной выкатки не удалась уборка; обновление успешно, уборку
  повторит следующий запуск.

## Выкатка и установка

- Обычная выкатка кнопкой.
