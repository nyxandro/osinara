# v0.54.0 — файлы и картинки внутри ответа, оформленные заметки, Google без лишних кнопок

Одна миграция (143, добавляет необязательное поле, данные не переписывает). Переиндексация памяти не
нужна, новых секретов нет, правила мониторинга не меняются.

## Что изменилось для пользователя

**Картинки и файлы приходят внутри ответа.** Раньше агент отправлял фото или документ отдельным
сообщением с короткой подписью, а текст — следующим сообщением. Теперь всё приходит одним сообщением:
- рецепт с обложкой сверху, заголовками, списками и фото этапов между шагами;
- отчёт с PDF прямо под текстом;
- картинка с подписью под ней.

Внутри ответа агент показывает:
- фото — картинку в пределах Telegram;
- видео — MP4;
- аудио — MP3;
- документ — всё остальное, в том числе GIF и слишком большие картинки.

В одном сообщении может быть до 50 файлов и до 47 МБ вместе. Ответ с несколькими картинками не прячется
под «Полный ответ» только из-за картинок. Если ответ длинный и сворачивается, картинка, стоящая первой,
остаётся видна над свёрнутым блоком.

**Картинку из интернета агент сначала сохраняет.** Агент не ставит в ответ ссылку на картинку с
чужого сайта: он скачивает её в свою папку и показывает уже файл. Для рецептов это ещё и полезно —
картинка не пропадёт, если сайт её удалит.

**Если файл приложить не удалось, это видно.** Если файла нет, путь указан неверно или файл слишком
большой, агент один раз исправляет ответ сам. Если и это не помогло, ответ всё равно приходит, а на
месте файла — строка «⚠️ Не удалось приложить «имя»: причина» с кодом для обращения.

**Заметки по ходу работы оформлены.** Текст, который агент пишет посреди долгой задачи, раньше
приходил без оформления — с видимыми `###` и `-`. Теперь он оформлен так же, как итоговый ответ.

**Кнопки под сообщением с файлами работают полностью.** После нажатия на месте кнопок появляется
«Выбрано», а картинки и файлы сообщения остаются на месте.

**Изменения в Google — по прямой просьбе, без кнопки подтверждения.** Отправка и пересылка писем,
удаление, правка календаря, документов, файлов и контактов выполняются сразу, если человек прямо об
этом попросил. Кнопку владельца по-прежнему требует только то, что открывает данные другим людям:
- доступ к календарю или файлам Drive;
- ответ на запрос доступа;
- публикация файла в интернете;
- передача почты в управление другому человеку.

## Безопасность

- **Права на файлы проверяет код.** Агент показывает в ответе только файлы из папок, доступных этому
  чату. Внешняя группа получает только файлы своей папки, личная и семейная папки ей недоступны.
  Модель не может прислать файл из чужой папки, сколько бы её об этом ни просили.
- **Telegram никогда не скачивает картинку по адресу, который выбрала модель.** Подпись под файлом
  проходит тот же фильтр ссылок, что и весь ответ: страница из интернета не спрячет в подписи ссылку
  на чужого бота.
- **В Google без человека только чтение.** В делегированной подзадаче и в сценарии по расписанию
  Google работает только на чтение. Там некому увидеть изменение, а текст прочитанного письма или
  страницы мог бы его подстроить. Подзадача сообщает основному агенту, что нужно изменить; сценарий
  пишет это в итоге.

## Для владельца и дежурного

- **Сразу после выкатки нужно переписать три скилла семьи.** Скиллы `recipes`, `doc-signing` и
  `online-ordering` велят пользоваться инструментом `send_workspace_file`, а его больше нет. Пока их не
  переписали, агент по ним будет звать несуществующий инструмент и обходиться без него. Достаточно
  попросить агента в личке обновить эти скиллы под отправку файлов внутри ответа.
- **Инструмент `send_workspace_file` удалён.** Во внешних группах его имя осталось в сохранённых
  списках прав и в возможностях сценариев. Оно по-прежнему читается, но ничего не выдаёт: файлы своей
  папки доступны всем внешним группам. Новым сценариям это право больше не предлагается. Голосовые
  ответы и GIF работают как прежде.
- **Миграция 143** добавляет к `telegram_reply_button_sets` необязательное поле `message_media`. В нём
  хранится, каким файлом Telegram стал каждый файл сообщения с кнопками. Старые записи не меняются.
- **Что смотреть в журнале после выкатки:**
  - `AGENT_ANSWER_FILES_NOT_ATTACHED` — часть файлов не ушла, вместо них человек увидел строки;
    причины в поле `problems`;
  - `AGENT_ANSWER_FILES_FORMAT_UNFIT` — ответ не поместился в оформленное сообщение вместе с файлами и
    ушёл без них;
  - `AGENT_ANSWER_FILES_REFUSED` — Telegram отказал сообщению с файлами, и оно ушло ещё раз без них;
  - `AGENT_ANSWER_CHECK_CORRECTION_FAILED` — исправление ответа не удалось, ушёл исходный ответ;
  - `AGENT_ANSWER_CHECK_FAILED` — сбой самой проверки файлов, например недоступна база; ход падает с
    понятным кодом, а не как «модель недоступна»;
  - `AGENT_TELEGRAM_RICH_MEDIA_RECEIPT_MISMATCH` — Telegram вернул не те файлы, что ожидались; под
    таким сообщением кнопки после нажатия могут остаться;
  - `AGENT_GOOGLE_WORKSPACE_SUBAGENT_WRITE_FORBIDDEN`, `AGENT_GOOGLE_WORKSPACE_SCENARIO_WRITE_FORBIDDEN` —
    подзадача или сценарий попытались изменить что-то в Google. Это ожидаемый отказ, не сбой.
- **Известное узкое место.** Если сервер остановится ровно между отправкой ответа с файлами и записью
  его кнопок, под этим одним сообщением кнопки после нажатия останутся. Выбор при этом засчитывается.
