# v0.53.0 — точный фильтр форматированных ответов, переносы строк и запасной путь для кнопок

Миграций нет, переиндексация памяти не нужна, новых секретов нет, правила мониторинга не меняются.
Добавлена библиотека разбора Markdown (`mdast-util-from-markdown`, `micromark-extension-gfm`,
`mdast-util-gfm`): через неё теперь проходит каждый форматированный ответ агента.

## Что изменилось для пользователя

**Строки ответа больше не склеиваются.** Если агент пишет «Итог:» и ниже пункты по одному в строке, вы
так их и увидите. Раньше в форматированных ответах Telegram показывал соседние строки через пробел,
одной сплошной строкой: так он читает одиночный перенос строки. Блоки кода, таблицы, заголовки и
обычные списки выглядят как раньше.

**Цитаты стали цитатами.** Строки, которые агент начинает со знака `>`, теперь показываются как цитата.
Раньше они приходили обычным текстом с этим знаком в начале.

**Примеры кода показываются точнее.**
- Код со знаком `$` (например, `IFS=$'\n'` в bash) приходит ровно таким, как написан. Раньше в такой блок
  кода мог подставиться кусок остального сообщения.
- Блок кода внутри пункта списка (например, в пункте «10.») показывает `<` и `>` как есть, а не `&lt;`.
- Если ответ оборвался посреди блока кода, блок закрывается, и ответ приходит, даже если он был внутри
  сворачиваемого блока.

**Ответ с кнопками не пропадёт, даже если Telegram их не примет.** Если Telegram откажет сообщению
из-за кнопок, то же сообщение придёт без них. Так же для напоминаний с кнопками.

## Безопасность

Агент читает веб-страницы, файлы и пересланные сообщения. Злоумышленник может спрятать там указание
вставить в ответ ссылку, которая открывает в Telegram чужого бота или чат (`tg://…`), или картинку с
чужого сайта. Фильтр перед отправкой обезвреживает такие вещи, но не трогает то, что считает кодом.
Раньше он угадывал границы кода самодельными правилами и ошибался там, где Telegram читает иначе:
- код в обратных кавычках, разорванный переносом строки;
- строка с отступом после абзаца;
- экранированная обратная кавычка;
- обратная кавычка внутри адреса ссылки;
- незакрытый блок кода внутри пункта списка;
- ссылки с подсказкой в кавычках, с пробелом перед адресом или в виде сноски.

Теперь границы кода, ссылок и HTML определяет разборщик Markdown, по тем же правилам, по которым
читает Telegram. Фильтр повторяет свою проверку на собственном результате, пока текст не перестанет
меняться: само обезвреживание может изменить, как прочитается остальное.

## Для владельца и дежурного

- **Код с отступом в четыре пробела вместо ``` считается текстом.** Telegram такой код не документирует,
  поэтому фильтр ему не доверяет: знак `<` в нём будет экранирован. Модель почти всегда пишет код в ```.
- **Что смотреть после выкатки:**
  - `AGENT_REPLY_BUTTONS_REJECTED` и `AGENT_REMINDER_BUTTONS_REJECTED`: Telegram отказал сообщению с
    кнопками, и оно ушло без них. Пояснение Telegram (до 200 символов) — в строке
    `AGENT_TELEGRAM_RICH_MESSAGE_DELIVERY_FAILED` рядом;
  - `AGENT_TELEGRAM_RICH_UNSETTLED` и `AGENT_TELEGRAM_RICH_LINKS_UNSETTLED`: текст так устроен, что
    проверка не пришла к устойчивому результату (обычно это специально подобранный текст). Ответ всё
    равно уходит, но целиком обезвреженный: без ссылок, картинок и тегов. Ожидается, что таких строк не
    будет.
- **Откат на v0.52.2 возможен.** Схема базы не менялась.
