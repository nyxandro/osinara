# v0.48.0 — доступ к устройствам в домашней сети по разрешению владельца

Миграция 138 (новая таблица разрешений). **Переиндексация памяти не нужна.** Правила мониторинга не
меняются. Новых зависимостей и секретов нет. Ручных шагов на сервере нет: новый том и проверки схемы
выкатки контроллер из этого релиза применяет сам.

## Что изменилось для пользователя

**Агент может работать с устройствами по IP-адресу**: Home Assistant, NAS, роутер, адреса Tailscale,
сервисы на нестандартных портах. Раньше песочница агента ходила только на обычные сайты по портам 80 и 443,
а любой IP-адрес отвергала.

**Доступ выдаёт только владелец — кнопкой в личном чате.** Когда агент упирается в такой адрес, он сам
просит доступ, и владельцу приходит карточка: «Адрес: 100.91.171.16:8123, Устройство: Home Assistant —
Да / Нет». Разрешение действует для песочниц семьи: команды, скрипты, браузер. Внешние группы и чтение
страниц (`web_fetch`) его не получают никогда.

**Доступами управляют словами**: «покажи, куда у тебя есть доступ», «отзови доступ к дому». После
отзыва новые запросы не проходят сразу, уже открытые соединения закрываются в течение 15 секунд.

**Часть адресов закрыта навсегда, даже с кнопкой**: сам сервер (`127.x`), служебная сеть Docker
(`172.16–172.31`), служебный адрес хостинга (`169.254.x`) и сети самого бота.

**Домашний адрес вроде `192.168.x.x` с сервера обычно недоступен.** Агент это знает и подскажет сначала
связать устройство с сервером туннелем — например, Tailscale на сервере и на устройстве — и дать ему
адрес из Tailscale (`100.x.x.x`).

## Для владельца и дежурного

- **Новый инструмент `manage_network_access`**: запросить, показать, отозвать. Работает только в личном
  чате владельца; в сценариях по расписанию и в подзадачах его нет — там некому нажать кнопку. Запрос
  запрещённого адреса или запрос не от владельца агент получает как отказ с причиной, ход не обрывается.
- **Описания инструментов личного чата выросли на 680 символов** (бюджет поднят до 26 700). Набор
  инструментов изменился, поэтому первый ответ в каждом длинном чате после выкатки будет медленнее, пока
  модель заново наполняет кэш.
- **Фильтр песочниц** пропускает IP-адрес на любом порту только для запросов из сети песочниц семьи и
  только по разрешению. Разрешения хранятся в базе, фильтр читает их копию
  `/app/network-access/grants.json` из нового тома `osinara-production-network-access`. Агент
  пересобирает этот файл из базы после каждого изменения и при каждом старте, поэтому том в резервную
  копию не входит.
- **Фильтр при старте находит свой адрес в сети песочниц** по имени `sandbox-trusted-egress-proxy`. Если
  имя не находится, фильтр не запускается: `AGENT_SANDBOX_EGRESS_TRUSTED_NETWORK_UNRESOLVED`.
- **Новые коды отказов фильтра**: `AGENT_SANDBOX_EGRESS_GRANT_REQUIRED` (нужно разрешение),
  `AGENT_SANDBOX_EGRESS_GRANT_SCOPE_FORBIDDEN` (запрос не из песочницы семьи),
  `AGENT_SANDBOX_EGRESS_DESTINATION_FORBIDDEN` (адрес закрыт навсегда),
  `AGENT_SANDBOX_EGRESS_GRANTS_UNAVAILABLE` (файл разрешений отсутствует или повреждён — все IP-адреса
  закрыты), `AGENT_SANDBOX_EGRESS_GRANTED_CONNECTION_CLOSED` (открытое соединение закрыто после отзыва).
  Как и прежние отказы фильтра, они считаются в `OsinaraErrorBurst`, порог прежний — больше 10 за
  5 минут.
- **Раньше фильтр отвергал любой IP-адрес, даже публичный** (`http://1.1.1.1`): он пытался найти IP через
  DNS и падал. Теперь IP без разрешения по-прежнему не проходит, но с понятной причиной.
- **Скрипт выкатки проверяет больше**: в сети песочниц семьи нет никого, кроме фильтра, имя
  `sandbox-trusted-egress-proxy` объявлено только там, а файл разрешений подключён к фильтру только для
  чтения. Новые правила проверяет контроллер из самого релиза.
- **Известное ограничение.** Собственные публичный адрес и адрес Tailscale сервера программно не
  закрыты: для них защита — только кнопка владельца. Подтверждайте адрес, только если это действительно
  ваше устройство. Разрешения действуют на весь сервер (одна семья — один сервер).
- **Откат** на v0.47.2 возможен: миграция 138 только добавляет таблицу, старый образ её не трогает. На
  время отката разрешения перестают действовать.
- В репозиторий добавлен план улучшений памяти после сравнения с форком Мии
  (`docs/plans/memory-after-mia-comparison.md`). Это документ, на работу бота он не влияет.
