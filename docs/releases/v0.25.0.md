# v0.25.0 — сигналы для внешнего наблюдения за работой Osinara

Osinara начала отдавать наружу то, по чему можно понять, что она работает, а не только то, что она
упала. Раньше ошибки были видны в логе, но самый неприятный сценарий — когда ничего не ломается,
а просто перестаёт происходить — выглядел как тишина. Теперь у планировщика есть пульс, а у
состояния очередей и фоновых задач — числовое выражение, доступное внешнему наблюдателю без
доступа к содержимому переписки и памяти.

## Что изменилось для пользователя

Поведение ассистента не меняется. Меняется то, как быстро владелец узнаёт о проблеме.

### Остановка планировщика перестала быть незаметной

- После каждого успешного цикла четырёх периодических диспетчеров (напоминания, автономные
  сценарии, проверка памяти групп, проверка обновлений) в лог пишется одна служебная строка.
- Если цикл завершился ошибкой, строка не пишется. Отсутствие строки и есть сигнал.
- Раньше остановившийся планировщик не давал вообще никаких следов: напоминания просто не
  приходили, и узнать об этом можно было только заметив пропажу.

### Состояние очередей и фоновых задач стало измеримым

Внешняя система наблюдения теперь может видеть, не читая ни одного сообщения:

- сколько входящих сообщений ждёт обработки и сколько времени ждёт самое старое;
- сколько уведомлений о сбоях не доставлено владельцу;
- сколько пакетов проверки памяти групп остановлено и по какой причине;
- сколько задач индексации памяти завершилось ошибкой, то есть какие воспоминания не находятся
  поиском;
- как давно был последний успешный ответ модели;
- не застряло ли приложение в режиме обслуживания, когда оно не принимает новую работу;
- сколько запусков расписаний прошло за сутки и с каким результатом.

## Границы доступа

Наблюдатель получает отдельную роль базы данных `osinara_metrics`. Она может читать только
представления `monitoring_*`, которые возвращают счётчики и возрасты, и право на каждое из них
выдано поимённо. Прав на таблицы с содержимым — память, сообщения, пользователи — у неё нет,
и попытка прочитать их завершается отказом базы. Представления исполняются с правами владельца, поэтому агрегаты
считаются корректно без выдачи доступа к исходным данным. Обе стороны границы проверены
интеграционным тестом.

Роль создаётся без права входа. Пароль ей выдаёт владелец один раз на сервере после релиза;
в репозитории, в файлах конфигурации и в списке процессов пароль не появляется.

## Действия администратора после релиза

Обязательных действий нет: без них приложение работает как прежде, просто внешние метрики не
собираются. Чтобы включить сбор, нужно один раз выдать роли пароль и положить три файла из
`infra/monitoring/` рядом со сборщиком. Порядок описан в `infra/monitoring/README.md` и
в разделе «External monitoring» инструкции по деплою.

## Технические детали

- Новый модуль `agent/lib/schedule-heartbeat.ts` с функцией `withScheduleHeartbeat`, которая
  выполняет цикл расписания и пишет строку `{"code":"AGENT_SCHEDULE_TICK","schedule":"..."}`
  только после успешного завершения. Ошибка пробрасывается без изменений, строка не пишется.
  Некорректное имя расписания отклоняется до запуска работы кодом
  `AGENT_SCHEDULE_HEARTBEAT_INVALID`.
- Все четыре файла в `agent/schedules/` обёрнуты этой функцией вокруг существующего
  `withRuntimeAdmission`; логика диспетчеров не изменилась.
- Миграция `103_monitoring_views.sql`: семь представлений `monitoring_*` (очередь входящих,
  инциденты, пакеты проверки памяти, задачи индексации, доступность модели, режим обслуживания,
  запуски расписаний), роль `osinara_metrics` с `NOLOGIN` и отдельный грант `SELECT` на каждое
  представление. Объекты создаются в текущей схеме, поэтому повтор обновления в изолированной
  схеме остаётся изолированным.
- Новый интеграционный тест `agent/lib/monitoring-views-migration.integration.test.ts` проверяет
  наличие роли, отсутствие права входа, доступ ко всем представлениям, отказ на таблицах с
  содержимым, исполнение каждого представления от имени самой роли и состав их колонок.
- Новая папка `infra/monitoring/` с конфигурацией экспортёра метрик, дополнением compose для
  сборщика и файлом опроса: описывают, что Osinara отдаёт, но частью релиза не являются.
- `compose.production.yaml`, образы приложения и контроллер деплоя не изменялись.
