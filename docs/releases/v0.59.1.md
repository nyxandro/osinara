# v0.59.1 — у ключей API свой ключ шифрования: фильтр песочниц больше не держит ключ, защищающий Google

Миграций нет, переиндексация памяти не нужна, правила мониторинга не меняются. **Новый секрет**
`SANDBOX_API_KEY_ENCRYPTION_KEY` — он должен быть в `/opt/osinara/.env` до выкатки (см. ниже).

## Что изменилось для пользователя

Ничего видимого: ключи API работают как в v0.59.0. Сохранённые ключи после выкатки перешифровываются
на новый ключ, присылать их заново не нужно.

## Безопасность

- Значения ключей API шифруются своим ключом `SANDBOX_API_KEY_ENCRYPTION_KEY`, а не общим
  `INTEGRATION_TOKEN_ENCRYPTION_KEY`, которым защищены токены Google.
- Фильтр песочниц (`sandbox-egress-proxy`), самая открытая трафику песочниц часть сервера, получает
  только новый ключ. Общий ключ интеграций остаётся у агента. Взлом фильтра больше не открывает
  токены Google даже вместе с копией базы.
- Тест сборки следит, чтобы общий ключ интеграций не попал в окружение фильтра.

## Для владельца и дежурного

- **До выкатки** в `/opt/osinara/.env` добавить строку `SANDBOX_API_KEY_ENCRYPTION_KEY=` с 32
  случайными байтами в base64 (`openssl rand -base64 32`). На боевом сервере это сделано вместе с
  релизом. Новые установки получают ключ от установщика. Без ключа владелец не может сохранить
  ключ (`AGENT_API_KEY_STORAGE_UNCONFIGURED`), а шлюз отказывает с
  `AGENT_SANDBOX_API_KEY_GATEWAY_UNAVAILABLE`. Остальной выход песочниц в интернет работает.
- **Ключи, сохранённые в v0.59.0,** зашифрованы прежним ключом, и после выкатки шлюз отвечает по
  ним `AGENT_SANDBOX_API_KEY_GATEWAY_UNAVAILABLE`. Постоянной команды перешифровки в релизе нет:
  - на боевом сервере единственный такой ключ разово перешифрован в контейнере агента сразу после
    выкатки, вместе с повторной публикацией файла для фильтра;
  - на любом другом сервере владелец просит агента в личке запросить ключ заново с тем же именем
    (адрес и заголовок прежние) и присылает его. Значение заменяется, выдачи и учёт сохраняются.
- Неверный или пустой ключ больше не останавливает фильтр: шлюз отказывает с
  `AGENT_SANDBOX_API_KEY_GATEWAY_UNAVAILABLE`, а в журнале фильтра при старте появляется
  `AGENT_SANDBOX_API_KEY_GATEWAY_UNCONFIGURED` с причиной. Остальной выход песочниц работает. В
  v0.59.0 неверный общий ключ останавливал фильтр, а за ним раннер песочниц и агента.
- **Смена этого ключа** делает все сохранённые значения нечитаемыми — после неё ключи присылают
  заново. Ключ хранится только в `.env`; без него сохранённые ключи не восстановить.
- **Что проверить после выкатки:** в журнале фильтра нет `AGENT_SANDBOX_API_KEY_GATEWAY_UNCONFIGURED`;
  запрос скилла группы через ключ отвечает 200 (`AGENT_SANDBOX_API_KEY_USED`).
