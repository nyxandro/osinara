# v0.29.0 — в группе агент сам решает, отвечать реплаем или отдельным сообщением

Небольшой выпуск из одной новой возможности и одного исправления сборки. Главное: в группах
агент перестал отвечать реплаем на каждое сообщение без разбора. Если его просят написать текст
для других людей, например объявление для соседей, он отправляет этот текст обычным сообщением,
без цитаты просьбы сверху. Второе изменение касается только сборки выпусков: она больше не падает
из-за лимита запросов GitHub.

Схема базы не меняется, миграций нет. **Переиндексация памяти не нужна.** Шагов вручную после
выкатки нет.

## Что изменилось для пользователя

### Текст для других людей приходит отдельным сообщением

Раньше каждый ответ агента в группе уходил реплаем на сообщение, которое его вызвало. Это правило
было жёстко зашито в код, и модель не могла на него повлиять. Когда агент отвечает самому автору,
так и нужно: в общем чате видно, кому адресован ответ. Но просьба «напиши соседям, что у нас
опять затопило» приводила к странному результату. Готовое объявление приходило ответом на
просьбу, с её цитатой сверху, и выглядело как реплика автору, а не как сообщение всему чату.

Теперь агент решает сам. По умолчанию всё как было: ответ автору остаётся реплаем. Если весь
ответ адресован не автору, а чату или другим людям (объявление, поздравление, готовый текст по
просьбе), агент отправляет его отдельным сообщением в тот же чат и ту же тему. Если в ответе есть
и слова самому автору, например пояснение к тексту, это обычный ответ, и он уйдёт реплаем. При
сомнении агент оставляет реплай.

Решение принимает модель, поэтому она может ошибиться в обе стороны: оставить реплай там, где он
лишний, или убрать его там, где он был бы уместен. Правило для модели сформулировано осторожно,
чтобы вторая ошибка случалась реже первой.

Как это устроено: модель ставит в начало ответа служебную пометку `[[no-reply]]`. Приложение её
вырезает и отправляет ответ без реплая. Люди эту пометку никогда не видят, в историю группы она
тоже не попадает. Устроено так же, как уже знакомая «мысль вдогонку» через `[[split]]`.

Что не изменилось:

- в личных чатах реплаев не было и нет;
- запросы на подтверждение действий по-прежнему приходят реплаем, чтобы было видно, к какой
  просьбе относятся кнопки;
- ответы по расписанию, как и раньше, приходят без реплая.

## Для эксплуатации

### Сборка выпуска не падает на лимите GitHub

При сборке приложение скачивает программу `gws` для работы с Google Workspace. Раньше она
скачивалась через REST API GitHub, а без авторизации он даёт 60 запросов в час на один адрес.
Машины CI делят адреса между собой, поэтому сборка v0.28.1 упала с ошибкой
`AGENT_GWS_DOWNLOAD_FAILED` (HTTP 403) и прошла только со второго запуска.

Теперь `gws` скачивается по обычной ссылке на файл релиза, у которой этого лимита нет. Защита от
подмены осталась прежней: сборка сверяет закреплённый SHA-256 архива и отвергает любой другой.

## Границы и хранение данных

- Правила доступа не менялись.
- **Пометка меняет только одно: будет реплай или нет.** Чат и тема, куда уходит ответ, берутся из
  проверенных данных текущего хода, а не из текста модели.
- **Проверка данных реплая выполняется всегда, даже если реплай не нужен.** Она подтверждает, что
  данные ответа относятся именно к этому чату. Так модель, в том числе из-за подброшенного в чат
  текста, не может заодно отключить эту проверку.
- **Повторная отправка не меняет выбор.** Решение «без реплая» входит в данные, по которым
  приложение узнаёт уже начатую доставку. Если отправку придётся повторить, ответ не превратится
  в реплай и не придёт дважды.
- В истории группы ответ по-прежнему связан с сообщением-просьбой, хотя в Telegram реплая нет.
  Так модель при следующих обращениях видит, на какую просьбу был написан этот текст.
- Внутри блоков кода пометка остаётся обычным текстом. Если модель напишет `[[no-reply]]` посреди
  обычного текста, пометка тоже сработает и будет вырезана, как и `[[split]]`.

## Проверки

- Полный прогон тестов в CI (Docker) зелёный на каждом изменении.
- Новые тесты: разбор пометки, включая блоки кода и сочетание с реакцией и `[[split]]`; решение о
  доставке; отправка через канал Telegram (реплай по умолчанию, без реплая по пометке,
  сохранение проверки чата).
- Изменение агента прошло независимое ревью отдельным агентом. Серьёзных проблем оно не нашло,
  но сделало пять мелких замечаний. Четыре исправлены до слияния; главное из них: в первом
  варианте при отдельном сообщении пропускалась проверка принадлежности данных реплая чату.
  Пятое, про пометку внутри текста, оставлено сознательно: так же ведёт себя `[[split]]`.
  CodeRabbit ревью этого изменения не запустил.
  Исправление сборки прошло ревью CodeRabbit без замечаний.
- **Не проверено до выкатки:** как модель выбирает между реплаем и отдельным сообщением в живом
  чате. Проверить после выкатки: попросить агента в группе написать объявление для соседей.
