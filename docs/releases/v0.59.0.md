# v0.59.0 — ключи API для скиллов: агент их не видит, а скилл пользуется ими и во внешних группах

Одна миграция (145, три новые таблицы; создаётся мгновенно), переиндексация памяти не нужна, новых
секретов нет: используется уже заданный `INTEGRATION_TOKEN_ENCRYPTION_KEY`. В правилах мониторинга
меняется только список исключений `OsinaraErrorBurst` — его нужно поставить на хаб после выкатки.

## Что изменилось для пользователя

**Ключ API больше не нужно писать в чат.** Попросите агента в личке «заведи ключ такого-то
сервиса». Агент найдёт адрес API сервиса и попросит приложение запросить ключ. Сообщение с запросом
присылает само приложение, а не модель, и в первой строке называет единственный адрес, куда будет
уходить ключ. Следующее ваше сообщение с ключом приложение перехватывает ещё до агента: шифрует,
удаляет из чата и подтверждает «Ключ сохранён». Ключ не попадает ни к модели, ни в историю.

**Скиллы пользуются ключом, не видя его.** В песочнице появляются две переменные: `<ИМЯ>_API_KEY`
— заглушка, бесполезная вне сервера, и `<ИМЯ>_BASE_URL` — адрес шлюза вместо адреса сервиса. Шлюз
сервера подставляет настоящий ключ в запрос и отправляет его только на адрес этого ключа. Если
спросить агента «покажи ключ», он увидит только заглушку.

**Ключ можно дать семье или внешней группе.** «Дай этот ключ группе …» — приходит карточка с
названием группы и адресом сервиса, ключ выдаётся после нажатия кнопки. Внешней группе для этого
нужен `bash`. Отозвать или удалить ключ можно в любой момент, со следующего же запроса он перестаёт
работать.

**Учёт без лимитов.** «Покажи ключи» — по каждой выдаче видно число запросов всего и за 7 дней и
время последнего.

**Защита от промахов.** Ожидание ключа длится 30 минут, любое обычное сообщение его отменяет и
уходит агенту как обычно. Ещё 24 часа после этого сообщение, похожее на ключ (присланное поздно или
повторно), удаляется и агенту не передаётся. Ключ вместе с другими словами тоже удаляется, с
просьбой прислать только сам ключ. Невидимые символы, которые иногда прихватываются при копировании,
из ключа вырезаются.

## Безопасность

- Ключ хранится в базе зашифрованным (AES-256-GCM, отдельный производный ключ). В песочницу, в
  историю и к модели значение не попадает.
- Шлюз узнаёт выдачу по заглушке и принимает её только из сети её чата: заглушка одной группы не
  работает из другой группы, а личная — из внешней группы. Ключ пишется только в свой заголовок и
  уходит только на сохранённый адрес по HTTPS с проверкой сертификата.
- У сохранённого ключа нельзя сменить адрес новым запросом. Если адрес меняется у ключа, который ещё
  ждёт значения, его выдачи семье и группам снимаются.
- Пока приложение ждёт один ключ, запрос другого отклоняется, чтобы ключ не сохранился под чужим
  именем.
- Инструмента нет у сценариев по расписанию и у подагентов.

## Для владельца и дежурного

- **Миграция 145:** таблицы `sandbox_api_keys`, `sandbox_api_key_grants`, `sandbox_api_key_usage`.
- **Фильтр песочниц** (`sandbox-egress-proxy`) теперь получает `INTEGRATION_TOKEN_ENCRYPTION_KEY` и
  адрес агента, слушает шлюз на внутреннем порту 3129 и отправляет агенту учёт на внутренний адрес
  `/v1/sandbox-api-key-usage`. Без ключа шифрования шлюз отвечает
  `AGENT_SANDBOX_API_KEY_GATEWAY_UNAVAILABLE`, а остальной выход песочниц в интернет работает как
  раньше.
- **Новые записи в журнале:**
  - агент: `AGENT_API_KEY_VALUE_STORED`, `AGENT_API_KEY_LATE_MESSAGE_WITHHELD`,
    `AGENT_API_KEY_INTAKE_REDELIVERED` (info); `AGENT_API_KEY_MESSAGE_DELETE_FAILED`,
    `AGENT_API_KEY_NOTICE_FAILED`, `AGENT_API_KEY_PUBLISH_FAILED` (error);
  - фильтр: `AGENT_SANDBOX_API_KEY_USED` (info) на каждый запрос через ключ;
    `AGENT_SANDBOX_API_KEY_NOT_GRANTED`, `AGENT_SANDBOX_API_KEY_UPSTREAM_FAILED` — отказ или
    недоступный сервис; `AGENT_SANDBOX_API_KEY_USAGE_REPORT_FAILED` — агент не принял учёт (во время
    выкатки ожидаемо, учёт отправится позже).
- **Правило `OsinaraErrorBurst`** больше не считает рутинные строки ключей: каждый запрос через
  шлюз (`AGENT_SANDBOX_API_KEY_USED`) и шаги приёма ключа владельцем. Пакет наблюдения ставится на
  хаб из тега релиза (`--target hub`); сборщик не меняется.
- **Что проверить после выкатки:** в личке попросить завести ключ сервиса, прислать его, убедиться,
  что сообщение исчезло; выдать ключ внешней группе и вызвать сервис из скилла группы; посмотреть
  список ключей и число запросов.
