# v0.36.0 — уборка следов прежнего фреймворка, часть 1

Код, тексты для модели и документация больше не ссылаются на прежний фреймворк Eve; заимствованный
из него код помечен одной строкой в шапке файла и перечислен в `THIRD_PARTY_NOTICES.md` вместе с
текстом лицензии Apache-2.0. Для семьи поведение не меняется. Внешние адреса переезжают с
`/eve/v1/…` на `/v1/…`; старые продолжают работать до следующего выпуска.

Миграций нет. **Переиндексация памяти не нужна.** Правила мониторинга изменились — пакет наблюдения
нужно раскатить на хаб: подсказки дежурному в `OsinaraIngressStuck` и `OsinaraTurnRunningLong` больше не
ссылаются на удалённую команду, из исключений `OsinaraErrorBurst` убраны четыре кода, которые больше
никто не пишет.

## Что изменилось для пользователя

- **Заметных изменений нет.** Ответы, кнопки подтверждения, вопросы, напоминания, сценарии и разбор
  памяти работают как раньше.
- **Тексты для модели переписаны без упоминаний Eve, смысл тот же:** системная строка о
  параллельном вызове инструментов, пометка об обрезанном при сжатии результате инструмента,
  сообщение об ошибке пакета скилла, описания инструментов Google Workspace и переноса фактов из
  внешних групп, инструкции встроенных скиллов Google Workspace. Маркер «промолчать» теперь `<empty-delivery/>`; старый маркер
  `<eve-empty-delivery/>` из уже записанной истории по-прежнему понимается как молчание.
- **Кнопки новых карточек подтверждения** отправляют префикс `hitl:`. Кнопки на карточках,
  показанных до выкатки, тоже работают.

## Для дежурного

- **До выкатки — владельцу:** добавить в Google Cloud Console (OAuth-клиент Osinara) второй адрес
  возврата `https://HOSTNAME/v1/google-oauth/callback`, старый `…/eve/v1/google-oauth/callback` не
  удалять до следующего выпуска. Без этого новое подключение Google Workspace после выкатки
  закончится ошибкой Google `redirect_uri_mismatch`; уже подключённые аккаунты продолжат работать.
- **После выкатки — перерегистрировать webhook Telegram** на `https://HOSTNAME/v1/telegram` с тем же
  секретом из `/opt/osinara/.env`. До этого Telegram продолжает слать на `/eve/v1/telegram`, и это
  тоже работает.
- **После выкатки — перевести проверку здоровья Traefik** с `/eve/v1/health` на `/v1/health` в файле,
  который Traefik действительно читает: на боевом сервере (установка до v0.24) это
  `/opt/osinara/tls/traefik-dynamic.yaml`, на установках новее — `/opt/osinara/tls/dynamic/osinara.yaml`.
  Проверка: `docker exec osinara-tls-traefik-1 grep -rn health /etc/traefik`. Сейчас работают оба
  адреса, но следующий выпуск старый отключит, и без этой правки Traefik снимет сайт с маршрута —
  webhook начнёт получать 503.
- **Адреса:** `/v1/telegram`, `/v1/google-oauth/callback`, `/v1/health` и внутренний
  `/v1/telegram-drain`. Старые `/eve/v1/…` обслуживаются тем же кодом. Контроллер выкатки этим
  выпуском не меняется и по-прежнему проверяет `/eve/v1/health`.
- **Убран ручной путь отмены зависшего сообщения Telegram** (код `AGENT_TELEGRAM_CANCELLATION_UNCONFIRMED`,
  команда `telegram-ingress-admin`). Этот код выдавал только прежний фреймворк; на боевой базе
  3 октября таких сообщений нет. Прерванное сообщение, как и раньше, подбирается заново после
  истечения аренды.
- **Неудачное удаление старого контекста больше не повторяется по кругу.** Сессия с ошибкой
  удаления остаётся с `cleanup_error_code` до разбора, следующие сессии удаляются как обычно.
- **Вопрос «продолжить разговор?» (`session-limit`) убран из карточек** — его задавал только прежний
  фреймворк.
- **Метка контейнера песочницы** с идентификатором сессии теперь `dev.osinara.sandbox.agent-session-id`;
  её никто не читает, уже запущенные контейнеры не пересоздаются.
- **Обновление с версий до v0.35 — только через v0.35.x.** Перенос истории из старой базы удалён:
  прямое обновление v0.34 → v0.36 начнёт все разговоры с пустого контекста.
- **Откат:** образы v0.35.0 остались на сервере, схема базы не менялась. После отката вернуть
  webhook на `/eve/v1/telegram` и проверку здоровья Traefik на `/eve/v1/health`: v0.35.0 новых
  адресов не знает. Кнопки карточек, показанных v0.36 (`hitl:`), v0.35.0 не понимает: такие
  подтверждения дождутся своего таймаута, их придётся запросить заново.
- **После выкатки проверить:** чаты отвечают; `curl https://HOSTNAME/v1/health` отвечает 200; после
  перерегистрации webhook сообщения приходят; в логе агента нет новых ошибок.
