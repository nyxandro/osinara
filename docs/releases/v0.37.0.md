# v0.37.0 — уборка следов прежнего фреймворка, часть 2

Контроллер выкатки больше не обращается к старой базе `osinara_workflow` и не знает о давних
переездах томов. Прежние адреса `/eve/v1/…`, префикс кнопок `eve:` и старый маркер «промолчать»
отключены. Том `sandbox-data`, которым ничто не пользовалось, убран из сборки.

Миграция одна: `125` переписывает старый маркер «промолчать» в сохранённой истории разговоров
(на боевой базе 3 октября — 7 сообщений в двух разговорах). **Переиндексация памяти не нужна.**
Правила мониторинга не менялись.

## Что изменилось для пользователя

- **Заметных изменений нет.**
- **Ассистент не напишет служебный маркер обычным текстом.** Прошлые ответы в истории, где модель
  молчала по-старому, переписаны на новое написание, поэтому модель не повторит то, что ядро больше
  не распознаёт.
- **Кнопки на карточках, показанных до v0.36,** больше ничего не делают (в логе агента одна строка
  `AGENT_TELEGRAM_CALLBACK_UNCLAIMED`). Ждущих ответа среди них нет: контроллер не начинает выкатку,
  пока подтверждение ждёт ответа.

## Для дежурного

**До выкатки — по порядку, на сервере с работающей v0.36:**

1. Webhook Telegram смотрит на `https://HOSTNAME/v1/telegram`; в Google Cloud Console есть адрес
   возврата `https://HOSTNAME/v1/google-oauth/callback`; проверка здоровья Traefik — на `/v1/health`
   в файле, который он читает (на боевом сервере `/opt/osinara/tls/traefik-dynamic.yaml`, проверка:
   `docker exec osinara-tls-traefik-1 grep -rn health /etc/traefik`). Старые адреса v0.37 не
   обслуживает: без этих правок бот замолчит, а Traefik снимет сайт с маршрута.
2. Установить новый контроллер выкатки из этого выпуска (`scripts/production-deploy.sh` в
   `/opt/osinara/bin` с правами `0:0:750`, `scripts/production-deploy/*.sh` в
   `/opt/osinara/bin/production-deploy` с правами `0:0:640`). На время замены остановить
   `osinara-deploy.timer` (он запускает контроллер раз в минуту) и включить после. Прежний
   контроллер эту версию не пропустит — он требует том `sandbox-data` и проверяет `/eve/v1/health`;
   новый работает и против v0.36, она уже отвечает на `/v1/…`.
3. Только после этого владелец одобряет обновление до v0.37. Одобрение, поданное раньше, прежний
   контроллер отклонит ещё до остановки сервисов — безопасно, но понадобится новое предложение.

**После выкатки:**

- Удалить освободившийся том: `docker volume rm osinara-production-sandbox-data`.
- `curl https://HOSTNAME/v1/health` отвечает 200; чаты отвечают; в логе `migrate` миграция `125`
  прошла.

**Что изменилось в контроллере:** проверка простоя смотрит только на базу приложения; резервная
копия содержит только базу приложения и тома приложения (старая база в предыдущих копиях осталась);
убраны мост v0.18.0 с переменной `WORKFLOW_POSTGRES_URL`, переезд томов v0.32 и разовое удаление
старого тома.

**Откат** на v0.36.0 возможен образами: схема не менялась, миграция `125` меняет только написание
маркера, а v0.36 понимает оба. Прежний контроллер для отката ставить не нужно.

## Что осталось на потом

**Выпуск 3, через неделю наблюдения:** переименование колонок `eve_*` в базе приложения, ключей
аудита и источников памяти в старом формате; удаление базы `osinara_workflow`, её роли и томов.
