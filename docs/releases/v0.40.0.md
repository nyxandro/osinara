# v0.40.0 — голосовые и файлы снова доходят до бота, факты внутри ответа проверяются

Чинит четыре места, которые сломались при переходе на собственное ядро в v0.35: функции Telegram,
перенесённые из прежнего фреймворка, раньше сами брали токен бота из окружения, а в нашем ядре его
нужно передавать явно. И расширяет правило проверки изменчивых фактов на сведения внутри ответа.

Миграций нет. **Переиндексация памяти не нужна.** Правила мониторинга не менялись.

## Что изменилось для пользователя

- **Статус «записывает голосовое…»** снова показывается, пока Осинара готовит голосовое. С v0.35 он
  не появлялся: в журнале агента была строка `AGENT_VOICE_RECORDING_STATUS_FAILED`.
- **Голосовые сообщения боту снова расшифровываются**, а **файлы и фото, присланные боту**, снова
  скачиваются. С v0.35 первое же такое сообщение не обработалось бы; по боевой базе на 3 октября
  ни голосовых, ни вложений в личку после v0.35 не приходило, так что ни один запрос не потерялся.
- **Карточка подтверждения с истёкшим временем** снова обновляется на «время истекло». После v0.35
  подтверждений не было.
- **Изменчивые факты внутри совета или рассказа тоже проверяются.** 3 октября в голосовом с советом,
  где пожить полгода, Осинара назвала аренду в Ереване и банки для россиян по памяти модели. Теперь
  любую конкретную цифру, цену, срок или условие из перечня изменчивых сведений она перед тем, как
  назвать, проверяет, а без проверки называет только с пометкой.

## Для дежурного

- Токен бота теперь явно передают статус записи голосового, расшифровка голосовых, скачивание
  вложений и правка карточки истёкшего подтверждения. Тесты вызывают именно эти боевые привязки и
  проверяют адрес запроса к Telegram: прежние тесты подставляли заглушки и ошибку не видели.
- **После выкатки проверить живым чатом:** прислать боту голосовое — оно расшифровывается; попросить
  ответ голосом — в чате видно «записывает голосовое…», в логе агента нет
  `AGENT_VOICE_RECORDING_STATUS_FAILED`; прислать файл и попросить его прочитать.
