# Osinara v0.22.3

## Агент сохраняет задачу при недоступной памяти

Исправлен случай, когда вместо запланированного дайджеста Osinara отвечала, что
«здесь нет запроса». Задача была получена и частично исполнена, но служебная пометка
о памяти перед каждым обращением к модели превращалась в последнее сообщение пользователя.

- Подборка памяти теперь остаётся в штатных системных инструкциях Eve текущего хода.
  Она не добавляет новое пользовательское сообщение и не меняет порядок результатов инструментов.
- Следующий ход получает собственную подборку; прежние записи не сохраняются в истории
  через этот механизм. Существующие проверки областей доступа и экранирование данных сохранены.
- При отказе памяти агент продолжает независимые части задания. Сведения, требующие
  недоступной памяти, обозначаются как непроверенные, а не придумываются.
- Удалён прежний механизм переноса контекста и заменены закреплявшие его тесты.

## Диагностика отказов памяти

- Сохраняются этап отказа, исходный код, идентификаторы сессии и хода; для фонового
  запуска дополнительно сохраняются идентификаторы запуска и расписания.
- Различаются проверка доступа, подготовка запроса, embeddings, поиск, темы памяти
  и профиль. Тексты личных запросов и записей в диагностику не копируются.
- Инцидент сохраняется существующим механизмом уведомлений владельца и переживает
  замену контейнера. Повтор одной записи не создаёт новый инцидент.
- Запись диагностики ограничена по времени: SQL — 1000 мс, ожидание ответа на запрос —
  1500 мс. Неисправное соединение удаляется из пула, поэтому зависшая диагностика
  не может бесконечно удерживать ответ пользователя.

## Google Workspace: правильные команды с первого загруженного skill

- Каждый отдельно загруженный Google skill сразу содержит правило исполнения через
  `execute_google_workspace`; оно больше не зависит от загрузки соседней инструкции.
- Для Gmail и Calendar даны готовые массивы аргументов. Сохранены знак `+` у helper-команд,
  отдельные элементы пути API и передача идентификаторов через `--params`.
- Отказ неизвестного маршрута сопровождается исполнимым примером получения справки.
  Такой отказ не объявляется потерей Google-авторизации.
- Google-профили остаются изолированными, изменения по-прежнему требуют штатного
  подтверждения Eve; бинарник и учётные данные не открываются обычным Bash-командам.

## Поиск: лимит сервиса не является найденной информацией

- HTTP 429 и наблюдавшееся текстовое уведомление Exa об исчерпании бесплатного лимита
  возвращаются как `AGENT_WEB_SEARCH_RATE_LIMITED`, даже без стандартного признака ошибки.
- Тайм-аут, повреждённый ответ и превышение размера сохраняют отдельные коды и причину.
- Обычные статьи о лимитах продолжают считаться результатами поиска.
- Автоматические повторы не добавлены. Сам размер доступной квоты Exa не изменён.

## Расписания и обновлённый AI-дайджест

- В задании явно указано локальное время с часовым поясом, рядом с UTC.
- `list_agent_schedules` показывает факты последнего запуска: состояние исполнения,
  подтверждение доставки и сохранённую диагностику памяти. Завершённое исполнение
  не выдаётся за независимую проверку качества результата (`taskOutcome: not_verified`).
- Подготовлен версионируемый сценарий AI-дайджеста: новости, важная почта, календарь,
  дни рождения и официальные курсы. Отказ отдельной зависимости обозначается в своём разделе.
- Для исключения повторов используется журнал действительно доставленных сообщений;
  обновляемый список источников хранится в личном рабочем файле вместо записи через `remember` в фоне.
- Адресная команда `.runtime/scripts/repair-ai-digest.js` сначала показывает изменения
  без записи. При применении проверяет контрольные суммы старого сценария, нового текста
  и источников, действующего владельца и состояние расписания.
- Исходные записи памяти сохраняются, существующие файлы не перезаписываются.
  Одновременные применения исключаются. Потеря подтверждения SQL после создания файла
  явно обозначается как частичное/неоднозначное выполнение и не запускает автоматический повтор.

## Проверки и совместимость

Проверены реальный lifecycle Eve, запросы generate/stream, блокировка таблицы диагностики,
права доступа, контрольные суммы, параллельный перенос и ошибка SQL после создания файла.
Последний полный локальный Docker gate: 2655 проверок прошли, три опциональные проверки
пропущены стандартной конфигурацией. После уточнений отдельно прошли 10 проверок переноса.
Чистая установка, проверка типов, обе сборки и свежий discovery manifest успешны.

Рабочая модель `qwen3.8-27b` проверена на синтетической истории инструментов: успех,
отказ памяти, лимит поиска, отказ почты. Во всех случаях сохранялась исходная задача.
Это не заменяет проверку реального выпуска дайджеста после установки.

Версии зависимостей, Compose-граф и схема БД не меняются. Пользовательский сценарий
обновляется отдельно адресной командой после установки кода, с сохранением расписания и получателя.
Первопричина исторического отказа памяти 13 сентября не установлена; выпуск исправляет
потерю задачи и делает следующие отказы диагностируемыми.

В корне `docs/` оставлены только анализ OpenViking и инструкция production-деплоя;
лишние отчёты удалены вместе со ссылками на них. Описания выпусков остаются в `docs/releases/`.
