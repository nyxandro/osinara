# v0.41.0 — автообновление из коробки, замеры качества памяти

Два направления в одном выпуске. Контроллер выкатки теперь едет внутри образа релиза и обновляет
себя сам. Появились замеры качества поиска памяти, на которых будет проверяться каждое следующее
улучшение памяти.

Миграций нет. **Переиндексация памяти не нужна.** Меняются правила мониторинга на хабе.
**Выпуск переводит прод на самообновляемый контроллер, поэтому до подтверждения обновления на
сервере один раз выполняется ручной шаг** (ниже).

## Что изменилось для пользователя

Ничего видимого. Ассистент отвечает и пользуется памятью так же, как в 0.40.3.

## Для владельца и дежурного

### Автообновление из коробки

- Контроллер выкатки (`scripts/production-deploy/`) лежит в app-образе релиза (`/app/deploy`).
  Перед каждой выкаткой он сверяет себя с копией из одобренного релиза. Если копия отличается, она
  проверяет сервер, становится текущей и продолжает ту же заявку. Ручная двухфазная смена
  контроллера перед релизами больше не нужна.
- `osinara install` сам ставит контроллер и включает таймер: подтверждённое обновление теперь
  применяется и на серверах, поставленных установщиком.
- Профиль сервера задаётся строкой `OSINARA_DEPLOYMENT_PROFILE=production|installation` в
  `/opt/osinara/.env`.
- **Разовый переход прода, до кнопки «Обновить»:** раздел «Moving a host to the self-updating
  controller (once)» в `docs/production-deployment.md`. Контроллер берётся строго из app-образа
  этого релиза (`images.app` в `osinara-deployment.json`), в `.env` добавляется
  `OSINARA_DEPLOYMENT_PROFILE=production`. Права проверяются через `stat`: `root:root`, `750` у
  каталогов и launcher, `640` у файлов. Следующий опрос таймера должен записать
  `DEPLOY_NO_APPROVED_PROPOSAL`. Контроллер не из образа этого релиза уронит выкатку с
  `DEPLOY_CONTROLLER_DIR_EXISTS`, а ту же версию повторно предложить нельзя.

### Замеры качества поиска памяти

- **Боевой сигнал.** В журнале подборки памяти у каждой показанной записи теперь есть её место и
  ветка поиска, которая её нашла. Ответ учитывается по служебной строке использования вместе с
  причиной завершения хода. На хабе добавлены правила записи (показано, использовано, ответы со
  служебной строкой, объём подборки) и тревога `OsinaraMemoryNeverUsed`: за трое суток при сотнях
  показов не использована ни одна запись. Офлайн-отчёт: `npm run memory:usage-report`.
- **Эталон на копии боевой базы** (`scripts/memory-quality/golden/`, стенд
  `compose.memory-golden-eval.yaml`). Это настоящие вопросы, копия базы, откатанная к моменту
  каждого вопроса, разметка вне репозитория и подсчёт точности, полноты и молчания подборки.
- **Синтетические замеры в CI.** Новая задача `retrieval-evals` гоняет наборы v3 и групповой с
  моделью векторов продукта, включая жёсткую проверку изоляции групп. Выпуск релиза её ждёт.
- **Замер ответов модели** (`scripts/memory-quality/answers/`): ответы модели продукта без
  подборки, с подборкой и с идеальной подборкой, оценка вслепую.
- Найденные замерами проблемы памяти заведены в issues #340–#348. Это план следующих выпусков.

### После выкатки

- Правила мониторинга: поставить пакет `infra/monitoring` этого тега на хаб
  (`add-project.sh … --target hub`, сначала `--dry-run`). Часть сборщика не менялась.
