# v0.82.0 — обновление ставится быстрее: без пересборки всего, без полной копии песочниц, без повторных тестов

Ускорение выпуска и выкатки (#577, PR #578). Для пользователей бота ничего не меняется. Меняется то, сколько
владелец ждёт от слияния до новой версии.

До этого выпуска путь занимал ~38 минут: 15 минут сборки на GitHub до кнопки и 17–23 минуты выкатки после неё,
из них бот был недоступен ~3,5 минуты. Замер выкатки v0.81.1 (25.11): скачивание образов — 4 мин, копия папок
песочниц — 14 мин, остановка с копией базы — 2,7 мин, запуск — 0,8 мин.

Миграций нет, переиндексация памяти не нужна, ручных шагов до и после кнопки нет. **Эта выкатка ещё долгая**:
образы собраны по-новому и скачиваются целиком, а первая копия песочниц в новом виде — полная. Ускорение видно
со следующего выпуска.

## Что изменилось для владельца

- **Сервер скачивает только то, что изменилось.** Раньше каждый релиз заново собирал все пять образов и сервер
  скачивал 12 частей образов (слоёв), даже где ничего не менялось: метки с номером версии и сам номер версии в
  `package.json` сбрасывали кэш сборки. Теперь метки ставятся на готовый образ, а пакеты ставятся из файлов без
  номера версии. Неизменённые слои — пакеты Node, системные пакеты песочницы — берутся из кэша и не
  скачиваются заново. Ожидаемо: скачивание ~1 минута вместо 4, сборка на GitHub на ~2,5 минуты короче.
- **Копия папок песочниц переносит только изменения.** Раньше перед каждым обновлением 6,5 ГБ рабочих папок
  бота сжимались целиком — 14 минут. Теперь каждая копия — папка: изменившиеся файлы записываются заново,
  остальные — ссылки на прошлую копию, те же байты на диске. Кэши, которые песочница скачивает сама (pip,
  браузеры Playwright, Chrome для puppeteer), не копируются. Копий по-прежнему три. Ожидаемо: 1–2 минуты вместо
  14, и время больше не растёт вместе с объёмом папок.
- **Простой короче.** Пока бот остановлен, контрольные суммы считаются только по копии базы и ключей Google, а
  не по гигабайтам архивов. Старая копия во время простоя только переименовывается, её файлы удаляются после
  запуска новой версии.
- **На GitHub тесты не гоняются дважды.** Релизный PR вливает в `main` ровно тот код, который минутами раньше
  прошёл обе проверки на `develop`. Теперь `main` сразу собирает релиз, если тот же код уже прошёл обе проверки
  в прогоне `develop`; в остальных случаях проверки идут, как раньше. Ожидаемо: сборка на GitHub ~3–5 минут
  вместо 15.

## Внутри

- Копия песочниц — `rsync` из образа релиза (в образ приложения добавлен пакет `rsync`), на самом низком
  приоритете процессора и диска, как и раньше. Новый модуль контроллера `scripts/production-deploy/live-copy.sh`.
- Комплект копии теперь: `postgres.dump`, архив ключей Google, `SHA256SUMS` (по этим двум файлам) и две папки —
  `osinara-production-tool-environments/` и `osinara-production-workspace-data/`. Старые комплекты с архивами
  уйдут из ротации за три выкатки.
- Неизменённые файлы — общие у всех копий: файлы внутри копии нельзя править вручную. Файл, записанный в
  песочнице под двумя именами, в копии — два отдельных файла. Как вернуть папки песочниц из копии — новый
  раздел инструкции деплоя.
- Известное ограничение: файл, который программа в песочнице переписала с тем же размером и тем же временем
  изменения (распаковка с сохранением времени, `cp -p`), попадёт в новую копию в прежнем виде.
- Решение о тестах на `main` принимает `scripts/ci/tested-tree-reuse.sh`; ручной запуск сборки всегда гоняет
  проверки.

## Наблюдение

- `DEPLOY_LIVE_COPY_FILES_VANISHED`, `DEPLOY_LIVE_COPY_FILES_CHANGED` — файлы песочниц удалены или изменены во
  время живой копии; копия хранит прочитанное, выкатка идёт дальше (принятый риск, как раньше у архива).
- `DEPLOY_LIVE_COPY_FAILED` — копия не удалась, выкатка остановлена до остановки бота. Заменяет
  `DEPLOY_LIVE_ARCHIVE_FAILED`.
- `DEPLOY_BACKUP_RETIRED` — старый комплект выведен из ротации во время простоя; `DEPLOY_BACKUP_PRUNED` — его
  файлы удалены после запуска; `DEPLOY_BACKUP_PRUNE_DEFERRED` — удалить не вышло, удалит следующая выкатка,
  само обновление успешно.
- В прогоне CI на `main` — задача `Tested tree`: заметка со ссылкой на прогон, проверки которого использованы,
  или предупреждение, почему проверки запущены.

## Выкатка и установка

- Обычная выкатка кнопкой. Эта — по времени как прежние: образы и копия песочниц делаются в новом виде с нуля.
  Уже сам этот выпуск собирается на `main` без повторных тестов, если сработает новая проверка.
- Свободное место: первая копия песочниц несжатая (~5,2 ГБ), на сервере свободно 56 ГБ.
