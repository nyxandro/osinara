# v0.24.0 — единый TLS-прокси Traefik и публикация через уже существующий прокси

Osinara избавилась от раздвоения TLS-слоя. До этой версии production работал на Traefik из
`infra/traefik/`, а установщик для чистой установки продолжал ставить Caddy из `infra/installer/`.
Теперь в репозитории один TLS-прокси, Traefik 3, и один источник его конфигурации, а установщик
умеет как поднять его сам, так и встроить Osinara в прокси, который на сервере уже работает.

## Что изменилось для пользователя

### Установка

- Установщик задаёт новый вопрос: «Как публиковать HTTPS для Osinara». Два ответа без значения по
  умолчанию: поставить Traefik от Osinara (нужны свободные порты `80` и `443`) или использовать уже
  работающий на сервере обратный прокси.
- В режиме собственного Traefik установка ведёт себя как раньше, только вместо Caddy поднимается
  Traefik 3.7.12 (образ закреплён по digest) в compose-проекте `osinara-tls`.
- В режиме внешнего прокси установщик не занимает порты `80` и `443`, ничего своего не запускает и
  до начала миграций проверяет, что `https://ИМЯ_ХОСТА` уже отвечает хоть каким-то HTTP-статусом.
  Если прокси не настроен, установка останавливается с кодом
  `OSINARA_INSTALL_EXTERNAL_PROXY_UNREACHABLE` и подсказкой, куда направить трафик
  (`127.0.0.1:8082` с хоста либо `edge:80` в сети `osinara-production-edge-frontend`). Ожидание
  публичного HTTPS в этом режиме увеличено с пяти до пятнадцати минут, чтобы успеть подключить
  контейнерный прокси к сети Osinara после появления edge.
- Требование к серверу в README уточнено: обязателен только свободный порт `8082`; порты `80` и `443`
  нужны лишь при установке собственного Traefik.

### Общий прокси для нескольких проектов на одном сервере

- Traefik теперь читает маршруты из каталога `/opt/osinara/tls/dynamic/`, а не из одного файла,
  и подхватывает изменения без перезапуска. Osinara владеет только файлом `dynamic/osinara.yaml`.
- Другой проект на том же сервере добавляет свой файл `dynamic/<проект>.yaml` со своими маршрутами.
  Переустановка Osinara перезаписывает только `osinara.yaml` и не трогает чужие маршруты.
- Файл `osinara.yaml` записывается и в режиме внешнего прокси: если снаружи тоже Traefik, его можно
  подключить как есть.

### Команды обслуживания

- `osinara status`, `doctor`, `logs` и `restart` теперь читают режим публикации из
  `/opt/osinara/tls/.env` (`OSINARA_TLS_MODE=managed|external`). В режиме внешнего прокси они не
  трогают чужой прокси: `doctor` и `restart` пропускают TLS-проект, `logs` возвращает `tls: null`.
- Имя compose-файла TLS-проекта унифицировано: установщик и команды обслуживания используют
  `/opt/osinara/tls/compose.yaml`, как в `infra/traefik/`, вместо прежнего `compose.tls.yaml`.
- Файл `tls/.env` без строки `OSINARA_TLS_MODE` отклоняется с кодом `OSINARA_OPERATION_TLS_ENV_INVALID`
  и подсказкой добавить строку. Режим по умолчанию не подставляется.

## Существующий production-сервер

Обязательных действий нет. Релиз разворачивает только проект `osinara-production`; Traefik на сервере
продолжает работать со своим текущим файлом маршрутов, а CLI `osinara`, которая читает новую строку
`OSINARA_TLS_MODE`, на серверах старого контроллера не установлена.

Переход на каталог `dynamic/` необязателен и описан в `docs/production-deployment.md`, раздел «TLS proxy».
Он полезен, когда к этому же Traefik подключается ещё один проект: маршруты каждого проекта живут в
своём файле, и никто не редактирует общий файл руками. Том `osinara-tls-traefik-data` с сертификатами
при этом сохраняется. Автоматического перевода с Caddy на Traefik для хостов, поставленных старым
установщиком, нет.

## Технические детали

- Удалены `infra/installer/Caddyfile` и `infra/installer/compose.tls.yaml`. Единственный источник
  TLS-конфигурации: `infra/traefik/compose.yaml` и `infra/traefik/dynamic/osinara.yaml`.
- Installation bundle вместо `installation/Caddyfile` и `installation/compose.tls.yaml` содержит
  `installation/traefik-compose.yaml` и `installation/traefik-osinara.yaml`; белый список записей
  в `installation-bundle.ts` и сборка в `build-installation-bundle.sh` обновлены.
- `InstallationExecutionInput` получил поле `tlsMode`; executor передаёт `{ hostname, tlsMode }`
  в `preflight`, `pullImages` и `waitForPublicHttps` и запускает `startTls` только в режиме `managed`.
- Контракт файла `tls/.env` вынесен в `buildTlsEnvironment` и `parseTlsEnvironment`
  (`host-contracts.ts`) и покрыт тестами на круговое преобразование и отказ при отсутствии режима.
- Список Docker-ресурсов, запрещённых при чистой установке, содержит `osinara-tls-traefik-data`
  вместо `osinara-tls-caddy-data`.
- Traefik запускается с `--providers.file.directory=/etc/traefik/dynamic --providers.file.watch=true`
  и монтирует `/opt/osinara/tls/dynamic` только на чтение.
- `compose.production.yaml`, образы приложения и контроллер деплоя не изменялись.
