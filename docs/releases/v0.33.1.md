# v0.33.1 — сценарий внешней группы снова может читать страницы

Из личного чата снова можно поставить сценарий для внешней группы, которому нужно читать
публичные страницы или искать в интернете. Например, ежедневную проверку новых релизов на GitHub
с отчётом в группу. До этого выпуска такой сценарий не создавался: агент получал отказ
`AGENT_EXTERNAL_SCHEDULE_CAPABILITY_NOT_GRANTED` («в целевой группе не разрешена capability
web_fetch»), хотя в обычных сообщениях той же группы чтение страниц работало.

Схема базы не меняется, миграций нет. **Переиндексация памяти не нужна.** Шагов вручную после
выкатки нет.

## Что изменилось для пользователя

- Сценарий внешней группы может использовать `web_fetch` и `web_search` без отдельного разрешения
  в политике группы — так же, как их используют обычные сообщения в этой группе.
- Остальные возможности сценария (например, отправка файла или поиск по памяти) по-прежнему
  требуют, чтобы они были разрешены в политике группы. Если возможность не разрешена, сценарий
  не создаётся, как и раньше.

## Причина

- С v0.14.0 сценарий внешней группы мог получить `web_fetch`, только если он записан в списке
  разрешённых инструментов группы.
- С v0.21.0 `web_fetch` и `web_search` стали базовыми инструментами каждой внешней группы: они
  выдаются всегда, а записывать их в список разрешённых инструментов группы запрещено.
- Проверку при создании сценария не обновили. Получилась взаимная блокировка: разрешить
  инструмент в политике группы нельзя, а без этого сценарий не создаётся.
- Тестовая группа в интеграционных тестах хранила `web_fetch` в политике по-старому, поэтому
  тесты этого не замечали.

## Как это устроено

- Проверка возможностей сценария при создании и при изменении теперь одна. Базовые инструменты
  группы разрешения не требуют, все прочие проверяются по текущей политике группы.
- Во время запуска чтение страниц проверяет, что группа по-прежнему зарегистрирована и что владелец
  не отозвал запуск, — как и прежде.
- Описание инструмента управления сценариями внешних групп теперь говорит модели, что `web_fetch`
  и `web_search` доступны без перечисления.
- Новый интеграционный тест повторяет боевую ситуацию: группа без `web_fetch` в политике —
  сценарий с чтением страниц создаётся и изменяется, а не разрешённая возможность по-прежнему
  отклоняется.
