# Qwen в NeuralDeep: проверка управления рассуждением

## Вывод

На проверенном endpoint установка `reasoning_effort: "low"` не даёт надёжного управления
рассуждением Qwen. NeuralDeep прямо пишет, что этот параметр для Qwen принимается, но не влияет.
Заявленные `thinking_token_budget` и `enable_thinking: false` на основном имени модели
в прямых запросах не обеспечили обещанное ограничение или отключение.

Рабочее отключение отдельного поля рассуждений обнаружено у `qwen3.8-27b-noreason`.
Этот алиас выдал корректный вызов тестового инструмента и принял синтетическую историю
с результатом инструмента. Однако в одном из двух одинаковых расчётов ответ оказался неверным,
а требование вернуть только сумму не соблюдалось в обоих. Это не оценка частоты ошибок модели,
но основание не переключать весь production на этот алиас без проверки реальных задач.

Production-конфигурация и код приложения в ходе эксперимента не изменялись.

## Текущая конфигурация

- Endpoint: `https://api.neuraldeep.ru/v1/chat/completions`.
- Основная модель production: `qwen3.8-27b`.
- Явное управление рассуждением: `agent.transport.reasoning = null`.
- Лимит вывода production: 16384 токена.
- Наш установщик сейчас предлагает только проверенную основную модель Qwen без вариантов
  reasoning. Вариант `-noreason` в локальный каталог приложения не добавлялся.

## Что обещает документация

Источник: [официальная полная справка NeuralDeep](https://neuraldeep.ru/llms-full.txt),
раздел "Текст / Chat completion", прочитан 7 сентября 2026.

- `reasoning_effort` для Qwen принимается, но не влияет.
- `chat_template_kwargs.thinking_token_budget` описан как потолок размышления.
- `enable_thinking: false` или алиас `-noreason` описаны как выключение размышления.
- Отдельные рассуждения передаются в `reasoning_content`.

Живой `GET /v1/models` объявляет для обеих моделей `tools: true`, `vision: true` и
`streaming: true`; `reasoning` равен true у основной модели и false у `-noreason`.
Это точнее краткого перечня моделей в документации, где tools у алиаса не перечислены.

## Методика

26 последовательных HTTP-запросов непосредственно из production-контейнера, без Eve,
с тем же ключом и endpoint. Ключ не выводился и не копировался в репозиторий.
В запросах только синтетические задания, без реальной переписки или памяти.
Инструменты в тестах не исполнялись и не выполняли внешние действия.

- `temperature: 0`, `max_tokens: 4096`, `stream: true`.
- `stream_options: { "include_usage": true }`.
- Одинаковый `user` внутри каждого задания для session-sticky routing.
- Клиентское ограничение одного запроса: 90 секунд, без повторов неудачных вызовов.
- Для выбранных режимов сделаны отдельные повторные измерения в обратном порядке.
- 23 запроса завершились, 3 были остановлены на 90 секундах с частичным рассуждением
  и без финального ответа. Их счётчики usage отсутствуют, а не равны нулю.

Измерены время заголовков, первого reasoning/ответа/tool call и окончания потока;
число Unicode-символов в полученном рассуждении; счётчик
`usage.completion_tokens_details.reasoning_tokens` непосредственно из API.
Символы не пересчитывались в токены. В отчёте нет текста внутренних рассуждений.

Несмотря на одинаковый `user` внутри задания, в ответах встретились два `system_fingerprint`:
`vllm-0.27.1-e41e8e97` и `vllm-0.27.1-tp2-0653e627`.
Поэтому различие задержек нельзя приписывать только настройке reasoning: сервер и нагрузка
тоже могут влиять. Даже два default-запроса с одинаковым хешем рассуждений заняли разное время.

## Расчёт

Одинаковое задание во всех 20 математических запросах:

> Лицензия стоит 1379 рублей в месяц. Купили 17 лицензий на 12 месяцев. На стоимость
> лицензий дают скидку 17%, затем вычитают купон 15000 рублей. После этого добавляют
> разовую настройку за 24990 рублей. На весь получившийся итог начисляют НДС 20%.
> Сколько всего к оплате? Округли только окончательный результат до копеек.
> Верни только сумму в рублях с двумя знаками после запятой.

Контрольный результат, проверенный независимо арифметикой: **292178.74 руб.**

Время в таблице включает весь поток до завершения; токены взяты из ответа API.
Два числа в ячейке относятся к двум отдельным измерениям, не к доверительному интервалу.

| Настройка | Токены рассуждения | Символы рассуждения | Время, с |
| --- | ---: | ---: | ---: |
| Без параметров | 344 / 344 | 721 / 721 | 12.46 / 35.61 |
| `reasoning_effort: low` | 263 / 161 | 602 / 376 | 30.27 / 27.64 |
| `reasoning_effort: medium` | 378 | 875 | 26.48 |
| `reasoning_effort: high` | 171 / 343 | 404 / 716 | 12.87 / 15.39 |
| `reasoning_effort: none` | нет usage | 230, частично | timeout 90 |
| `thinking_token_budget: 64` | 318 / нет usage | 933 / 800, частично | 9.93 / timeout 90 |
| `thinking_token_budget: 256` | 951 | 3032 | 27.77 |
| `thinking_token_budget: 1024` | 658 | 1920 | 22.77 |
| `low` + бюджет 64 | 840 | 2618 | 27.09 |
| `chat_template_kwargs.enable_thinking: false` | 343 / нет usage | 716 / 630, частично | 11.37 / timeout 90 |
| `enable_thinking: false` на верхнем уровне | 344 | 721 | 14.29 |
| `thinking: {type: disabled}` | 343 | 716 | 13.75 |
| `enable_thinking: false` + бюджет 0 внутри `chat_template_kwargs` | 819 | 2590 | 21.80 |
| Модель `qwen3.8-27b-noreason` | 0 / 0 | 0 / 0 | 7.68 / 10.23 |

Все завершившиеся расчёты основной модели дали правильную сумму. У `-noreason` первый
результат правильный, второй **292298.26** вместо **292178.74**. В обоих ответах алиаса
вместо одной суммы выведены промежуточные вычисления.

Тот факт, что результат для бюджета 1024 оказался ниже 1024, не доказывает работу потолка:
ограничения 64, 256 и 0 явно не соблюдались. Параметр бюджета изменял число входных токенов
в типичных ответах с 185 до 197; это наблюдение не доказывает механизм его обработки сервером.

## Инструменты

Первое задание требовало вызвать синтетический `lookup_public_info` для поиска текущей версии
PostgreSQL. Проверялись `finish_reason: tool_calls`, имя функции и JSON аргументов.
Реальный поиск не выполнялся.

| Режим | Токены рассуждения | Символы | Время, с | Вызов инструмента |
| --- | ---: | ---: | ---: | --- |
| Default | 50 | 247 | 15.90 | Корректный |
| Бюджет 64 | 44 | 227 | 4.61 | Корректный |
| `enable_thinking: false` | 49 | 246 | 4.89 | Корректный |
| `-noreason` | счётчик отсутствует | 0 | 2.37 | Корректный |

Отдельная проверка передавала заранее составленную синтетическую историю с tool call и
tool-result `{"version":"probe-v1","source":"synthetic fixture"}`. Обе модели прочитали
результат и вернули `probe-v1`: default за 2.32 с (23 reasoning tokens), `-noreason` за
1.03 с (0 reasoning tokens). Это проверка формата API, не полный прогон агента с реальными
инструментами, подтверждениями, памятью и длинной историей.

## Решение

1. Не менять `null` на `low` как якобы проверенное решение задержек. Надёжного управляемого
   низкого режима для основной Qwen на этом endpoint эксперимент не установил.
2. Передать NeuralDeep минимальное воспроизведение: основной model ID, `temperature: 0`,
   `chat_template_kwargs: {"enable_thinking":false,"thinking_token_budget":0}` и полученные
   819 reasoning tokens. Нужен работающий контракт или исправление документации/маршрутизации.
3. `-noreason` рассматривать только после проверки прикладных сценариев. Выключение работает,
   но найденная ошибка расчёта не позволяет рекомендовать слепую глобальную замену.
4. Ограничение времени всего запроса, остановку при провале обязательной подготовки и безопасный
   порядок резервных копий исправлять независимо. Три прямых запроса с коротким синтетическим
   входом не завершились за 90 секунд даже без промпта приложения и без его очередей.

На этом этапе выполнено только исследование. Production остаётся с исходной конфигурацией;
три перечисленные задачи надёжности этим отчётом не считаются реализованными.
